## 踩过的坑（排错记录）
1. 中文类名 `你好世界` 与文件名不匹配 → ParseError
2. 点 Build（锤子）≠ Run（绿三角），Build 只编译不执行
3. 运行配置「主类」字段填成了 .class 文件路径 → 找不到主类；应填类的全限定名
4. IDEA 运行配置「脚本」字段被误填成 python.exe 路径
5. **包结构坑（本轮重点）**：用户把 `hello\` 目录 Mark as Sources Root，导致 hello 不是"包"而是源码根，文件里的 `package hello;` 会与目录层级冲突。正确做法：Sources Root = 项目根（或 src），`hello\` 作为其下的子目录才是包。
6. **编译产物残留坑**：`out/production/chapter-1/hello/HelloWorld.class` 是旧产物（那时源码带 package），当前源码已无 package 声明。命令行 `java hello.HelloWorld` 能跑是**旧的 .class 在生效**，重新构建后就会失效 —— 属于"看起来能跑其实不一致"的隐患，必须 Rebuild + 清理验证。
7. **坑 8：cd 到包目录运行带包类**（命令行方式踩坑）。用户按实验文档步骤"cd 到 hello 目录再 javac + java"：在 hello/ 下 `javac HelloWorld.java` 会生成 `hello/hello/HelloWorld.class`（多一层），然后 `java HelloWorld` 报 `NoClassDefFoundError: HelloWorld (wrong name: hello/HelloWorld)`。
   根因：带包类运行时必须用 `包名.类名`（即 `java hello.HelloWorld`），不能只写类名。
   **正确做法：从项目根运行** `cd F:\新建文件夹 && java hello\HelloWorld.java`（Java 11+ 单文件模式，最省事）。
   这也是为什么实验报告截图应该在**项目根目录**下截，不是包目录。

## 新暴露的坑 7：源码根 = 项目根导致非源码目录被复制
Rebuild 后 IDEA 把根目录下所有非 .java 文件当资源复制进输出目录：
```

out/production/chapter-1/.workbuddy/memory/ ← 被复制
```

**根治方案：建 `src\` 目录，把 `hello\` 移进去，Sources Root 指向 `src`**（Maven/IDEA 标准布局）。
